# ELYRA — AI Character Roleplay Local MVP

เดโม Web Application สำหรับสร้างตัวละครและคุยกับ AI รองรับ **Cloud API (xAI / OpenAI)** และ **Local Ollama** ผ่าน backend เดียวกัน พร้อมโหมดจำลองที่ใช้ได้ทันทีโดยไม่ต้องเรียก AI

## เริ่มใช้งาน

ต้องมี **Python 3.11 ขึ้นไป** ไม่มีแพ็กเกจภายนอกที่ต้องติดตั้ง

```powershell
cd "D:\ELYRA AI"
python app.py
```

เปิด **http://localhost:3000** หรือดับเบิลคลิก `start.bat` หากพอร์ตไม่ว่าง:

```powershell
python app.py --port 3001
```

กด `Ctrl+C` ในเทอร์มินัลเพื่อหยุดเซิร์ฟเวอร์

## เปิดจากมือถือหรือเครื่องอื่นใน LAN

ค่าเริ่มต้นยังรับเฉพาะ localhost หากต้องการใช้ IP ของเครื่องนี้ ให้หยุดเซิร์ฟเวอร์เดิมก่อน แล้วรัน:

```powershell
python app.py --lan 192.168.1.181
# หรือ start.bat --lan 192.168.1.181
```

เปิด **http://192.168.1.181:3000** จากอุปกรณ์ในเครือข่ายเดียวกัน และยังใช้ http://localhost:3000 บนพีซีได้ ต้องใช้ IP ที่กำหนดให้เครื่องนี้จริง หาก IP เปลี่ยน ให้เปลี่ยน `--lan` ด้วย ระบบตรวจ Host/Origin แบบเจาะจงและยังต้องใช้ mutation token

ถ้าอุปกรณ์อื่นยังเชื่อมต่อไม่ได้ ให้เปิด PowerShell แบบ **Run as administrator** แล้วรันหนึ่งครั้ง:

```powershell
powershell -ExecutionPolicy Bypass -File "D:\ELYRA AI\enable-lan-firewall.ps1"
```

สคริปต์เพิ่มกฎเฉพาะ Python, IP นี้, TCP 3000 และเครื่องใน LocalSubnet ไม่ปิด Windows Firewall ใช้ได้แม้เครือข่ายนี้ถูกจัดเป็น Public หากเปลี่ยน IP/พอร์ต ส่ง `-LanAddress` / `-Port` ให้สคริปต์ด้วย

LAN mode ใช้ข้อมูลและสิทธิ์ชุดเดียวกันทุกอุปกรณ์ ยังไม่มีบัญชีแยกผู้ใช้ ใช้กับเครือข่ายที่ไว้ใจได้ และไม่ทำ port forwarding ออกอินเทอร์เน็ต

## ทดลองฟีเจอร์

1. หน้า **ค้นพบ**: เลือก Luna, Kael, Mira หรือ Ren แล้วเริ่มพูดคุย
2. โหมดเริ่มต้น **Demo**: คำตอบเขียนล่วงหน้า ไม่ใช่โมเดล AI และไม่เสียค่า API
3. คุยครบ **1 / 3 / 6 รอบ** จะปลดล็อกภาพ First light / Little rituals / Under the stars ในอัลบั้ม เป็นกติกาจำลองของ milestone ไม่ใช่ AI วิเคราะห์เหตุการณ์
4. กด **บันทึกความจำ** ใต้ข้อความ หรือเพิ่มความจำในแถบข้อมูลตัวละคร ความจำแยกตามห้องและลบได้
5. กด **สร้างตัวละคร** เพื่อกำหนดชื่อ อายุ บุคลิก ประวัติ รูปลักษณ์ ความสัมพันธ์ คำทักทาย และ **เคล็ดลับเริ่มเรื่อง** ที่แสดงให้ผู้อ่านเห็นในโปรไฟล์และหน้าแชต
6. หน้า **ตั้งค่า**: เลือกผู้ให้บริการ ทดสอบการเชื่อมต่อ เลือกโมเดล และบันทึกค่าเริ่มต้นสำหรับห้องใหม่ ห้องเก่าเปลี่ยน provider ได้จากหน้าแชต
7. เริ่มบทใหม่เพื่อสร้างห้องแยก โดยเก็บเรื่องราวเดิมไว้ หรือใช้ปุ่มถังขยะเพื่อลบห้องพร้อมข้อความ ความจำ และประวัติภาพปลดล็อกของห้องนั้น
8. ส่งออกตัวละคร บทสนทนา ความจำ สรุปเรื่องราว และรูปอัปโหลดเป็น JSON ได้ในหน้าตั้งค่า (ยังไม่มีหน้าจอนำเข้าข้อมูล)

## ตัวละคร ภาพ และเรื่องราวต่อเนื่อง

- อัปโหลดรูปโปรไฟล์และภาพ milestone ของตัวละครเองได้ รองรับ PNG/JPEG/WebP ต้นฉบับไม่เกิน 10 MB เบราว์เซอร์ย่อด้านยาวเหลือไม่เกิน 1,200 px และแปลงเป็น PNG/JPEG ก่อนส่ง รูปที่เก็บต้องไม่เกิน 2 MB เก็บใน SQLite โดยไม่เก็บชื่อไฟล์ต้นฉบับ
- รูป milestone ปรากฏในแชตอัตโนมัติเมื่อครบ 1/3/6 รอบ พร้อมสะสมในอัลบั้ม ยังใช้กติกาจำนวนรอบ ไม่ใช่ AI วิเคราะห์เหตุการณ์หรือสร้างภาพสด
- แก้ไข ทำสำเนา เก็บเข้าคลัง และนำตัวละครกลับมาได้ ตัวละครต้นแบบต้องทำสำเนาก่อนแก้ไข ห้องเดิมเก็บบุคลิกและข้อมูลตัวละครเวอร์ชันที่ใช้เริ่มเรื่อง ห้องใหม่ใช้เวอร์ชันล่าสุด ส่วนรูปโปรไฟล์ในแถบข้อมูลและภาพพื้นหลังใช้รูปปัจจุบัน เปลี่ยนได้จาก **ฉัน → แก้ไข → รูปโปรไฟล์ตัวละคร → เลือกรูป → บันทึกการแก้ไข**
- **สรุปเรื่องราว · AUTO** ในแถบข้อมูลใช้ AI สรุปแชทส่วนเก่าอัตโนมัติเมื่อบทสนทนายาวขึ้น ทำงานเบื้องหลังหลังคำตอบจบและอัปเดตหน้าจอโดยไม่ต้องรีเฟรช เก็บข้อความล่าสุดไว้แบบเต็มตามขนาดบริบท ไม่เรียกโมเดลสรุปซ้ำเพื่อแสดงผล โหมด Demo ไม่เรียก AI บันทึกที่เคยเขียนเองยังอยู่ในหัวข้อ **บันทึกเดิมของคุณ** และไม่ถูกเขียนทับ
- **แตกเส้นเรื่องจากตรงนี้** ใต้คำตอบจะสร้างห้องใหม่ถึงจุดที่เลือก คัดลอกเฉพาะความจำที่มีอยู่ก่อนจุดนั้น และเริ่มสรุปเรื่องราวว่างเพื่อไม่ให้ข้อมูลอนาคตติดไป
- จำกัดบริบทตามขนาด UTF-8: Cloud 96,000 bytes / Ollama 6,400 bytes เลือกคู่ข้อความล่าสุดที่ใส่ได้พร้อมสรุปส่วนเก่า ไม่ใช่การนับ token จริง ประวัติเต็มยังอยู่ในฐานข้อมูล แต่ไม่ส่งทุกข้อความให้ AI เมื่อแชตยาว สรุปเบื้องหลังเริ่มเมื่อข้อความที่ยังไม่สรุปเกิน 40,000 bytes สำหรับ Cloud หรือ 2,400 bytes สำหรับ Ollama (ใช้เกณฑ์เดิม ไม่สรุปใหม่ทุกข้อความ)
- ช่องพิมพ์เก็บฉบับร่างใน session ของแท็บ มี request ID ป้องกันคำขอเดิมบันทึกซ้ำหรือเรียกโมเดลซ้ำหลัง commit สำเร็จ การตอบที่ยังไม่จบอาจต้องเรียกใหม่และคิดค่า API ใหม่

เมื่อเปิดฐานข้อมูลเดิมครั้งแรก ระบบสำรองก่อน migration เป็น `.data/elyra.before-mvp.sqlite3` แล้วเพิ่ม snapshot ของตัวละครให้ห้องเก่า ห้ามลบฐานข้อมูลจริงเพื่อแก้ปัญหา migration

บนมือถือ เมนูเปิดจากปุ่มมุมซ้ายบน และข้อมูล/ความจำของห้องเปิดจากปุ่มข้อมูลด้านขวา เว็บปรับเลย์เอาต์ตามขนาดหน้าจอ

## เชื่อมต่อ xAI

1. คัดลอก `.env.example` เป็น `.env` และกำหนด `XAI_API_KEY` ฝั่งเซิร์ฟเวอร์
2. เริ่มเซิร์ฟเวอร์ใหม่
3. เปิดหน้าตั้งค่า → xAI → ตรวจสอบการเชื่อมต่อ → เลือกชื่อโมเดลที่บัญชีคุณรองรับ → บันทึก

สำหรับ workspace นี้ backend รองรับการอ่านไฟล์ `xAi_api_key.text` ที่ผู้ใช้เตรียมไว้แล้วโดยตรง หากไม่ได้ตั้ง `XAI_API_KEY` โดยจะไม่คัดลอกไฟล์หรือส่ง key ไปที่เบราว์เซอร์

การกดตรวจสอบการเชื่อมต่อเรียกเฉพาะรายการโมเดล การส่งแชตจริงมีค่าใช้จ่ายตามบริการและบัญชีของคุณ ชื่อโมเดลที่ใช้ได้ขึ้นกับสิทธิ์บัญชี จึงไม่กำหนดชื่อ Cloud model แบบตายตัว

## เชื่อมต่อ OpenAI

กำหนด `OPENAI_API_KEY` ใน `.env` แล้วทำขั้นตอนเดียวกันในหน้าตั้งค่า ใช้ Responses API พร้อม streaming และ `store: false` โดยเก็บประวัติหลักไว้ใน SQLite ของแอป การตั้งค่านี้ไม่ได้หมายความว่าไม่มีการเก็บข้อมูลทุกประเภทโดยผู้ให้บริการ โปรดตรวจนโยบายข้อมูลของบัญชีที่ใช้

## เชื่อมต่อ Local Ollama

1. ติดตั้งและเปิด Ollama บนเครื่องเดียวกับ Python
2. ดาวน์โหลดโมเดลที่เหมาะกับฮาร์ดแวร์ของคุณ
3. หน้า Settings → Ollama → ตรวจสอบการเชื่อมต่อ → เลือกชื่อโมเดลที่ดาวน์โหลดไว้ → บันทึก
4. สร้างห้องใหม่ หรือเลือก Ollama ในหัวห้องเดิม

ค่าเริ่มต้นคือ `http://127.0.0.1:11434` เปลี่ยนได้ด้วย `OLLAMA_BASE_URL` ใน `.env` เดโมจำกัด endpoint นี้เป็น loopback และ **ไม่สลับไป Cloud อัตโนมัติ** หาก Ollama ไม่พร้อม

Ollama คือ runtime ส่วนคุณภาพภาษาไทย ความเร็ว และการรักษาคาแรกเตอร์ขึ้นกับโมเดลและฮาร์ดแวร์ แอปส่งบุคลิก ความจำที่บันทึก และข้อความล่าสุดให้โมเดลทุกครั้ง ยังไม่มีการสรุปประวัติเก่าอัตโนมัติ

## ขอบเขตของเดโม

- เป็น **single-user development server** ค่าเริ่มต้นผูกกับ `127.0.0.1` และเปิด LAN ได้ด้วย `--lan PRIVATE_IP` ไม่มีระบบบัญชีผู้ใช้หรือ production authentication และไม่ได้เผยแพร่ขึ้นอินเทอร์เน็ต
- รองรับเลย์เอาต์มือถือ เปิดจากโทรศัพท์ผ่าน IP ของพีซีในโหมด LAN; `localhost` ของโทรศัพท์ไม่ใช่เครื่องพีซี
- เนื้อหาทั่วไป โรแมนซ์ และธีมดราม่าสำหรับผู้ใหญ่เท่านั้น **ไม่เปิดเนื้อหาทางเพศโจ่งแจ้ง** ตัวละครต้องอายุอย่างน้อย 18 ปี
- การยืนยันอายุในเดโมเป็น self-declaration ไม่ใช่ age verification สำหรับเปิดบริการจริง
- ขอบเขตเนื้อหาใช้คำสั่งระบบเบื้องต้น ยังไม่มีระบบ moderation/รายงาน/ตรวจอายุสำหรับ production การใช้ Local ไม่ยกเว้นกฎหมาย ใบอนุญาตโมเดล หรือกติกาแพลตฟอร์ม
- มีภาพ **SVG ที่สร้างในโปรเจกต์** 4 ชุด และรองรับภาพอัปโหลดของผู้ใช้ ไม่มีการสร้างภาพสด รายละเอียด appearance ใช้ในบริบทแชต
- ภาพเดโมเป็น static assets สาธารณะภายในเซิร์ฟเวอร์ การล็อกภาพเป็นสถานะสะสมในแอป ไม่ใช่ระบบป้องกันไฟล์พรีเมียม
- แชตเก็บเป็นข้อความธรรมดาใน SQLite บนดิสก์ ไม่ใช่ end-to-end encryption
- สตรีมที่ผิดพลาดจะไม่บันทึกคู่ข้อความหรือปลดล็อกภาพ สามารถส่งใหม่ได้ ไม่มีการ fallback provider แบบเงียบ
- การส่งซ้ำจากแท็บเดิมใช้ request ID เดิมเมื่อข้อความตรงกัน Backend ตรวจคำขอที่ commit แล้วและคืนห้องปัจจุบันโดยไม่สร้างคำตอบหรือปลดล็อกภาพซ้ำ

## โครงสร้าง

```text
app.py                  HTTP server, API, streaming, access checks
elyra/domain.py          ตัวละครเริ่มต้น บุคลิก และกติกา milestone
elyra/providers.py       OpenAI / xAI / Ollama adapters
elyra/store.py           SQLite persistence
elyra/context.py         ประกอบบริบทภายใต้ขนาดที่กำหนด
elyra/media.py           ตรวจภาพ PNG/JPEG ก่อนบันทึก
public/                 HTML, CSS, JavaScript และภาพ SVG
tools/build_assets.py   สร้างภาพ SVG เดโมใหม่
tests/test_app.py       Integration และ adapter tests แบบไม่เรียก API จริง
tests/test_mvp.py       ภาพ ตัวละครเวอร์ชัน ห้องแยก migration และ retry
.data/elyra.db          ข้อมูลผู้ใช้ สร้างอัตโนมัติและไม่อยู่ใน Git
.env                    การตั้งค่าและ secrets ฝั่งเซิร์ฟเวอร์ ไม่อยู่ใน Git
```

## ตรวจสอบ

```powershell
python -m unittest discover -s tests -v
python -m compileall -q app.py elyra tools
```

ชุดทดสอบใช้ฐานข้อมูลชั่วคราวและ upstream จำลอง ไม่เปลี่ยนแชตจริง ไม่ใช้ key และไม่เสียค่า API ครอบคลุมการแยกความจำ การสลับ provider การปลดล็อกภาพ การลบข้อมูล การป้องกันการเปิดไฟล์ secrets และการรับมือสตรีมขาด

ผลตรวจล่าสุด: **36 offline tests ผ่าน** และ Chrome Desktop/Mobile ผ่านทั้งฟีเจอร์เดิมและฟีเจอร์ MVP รวมอัปโหลดภาพ แก้ไขตัวละคร แชต snapshot สรุปเรื่องราว แตกเส้นเรื่อง คลังตัวละคร และกู้ฉบับร่าง ไม่มี JavaScript console error

มี `tools/browser_qa.py` และ `tools/browser_mvp_qa.py` สำหรับ smoke test ผ่าน Chrome DevTools ที่พอร์ต 9223 ใช้ฐานข้อมูลแยกใน `.qa/` และบันทึกภาพหน้าจอ Desktop/Mobile โดยไม่แตะประวัติจริง ต้องเปิด Chrome สำหรับทดสอบไว้ก่อนจึงจะรันสคริปต์เหล่านี้ได้

เพิ่ม authentication และการแยกสิทธิ์ข้อมูลรายผู้ใช้, moderation และระบบรายงาน, การตรวจอายุที่เหมาะสม, สรุปเรื่องราวอัตโนมัติ, event extraction แบบ structured output, rate limit/ต้นทุน/โควตา, และ backend ที่ deploy ได้พร้อม secret management ก่อนทำ native app
